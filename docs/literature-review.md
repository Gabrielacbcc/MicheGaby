# Literature Review

ResumeLens processes unstructured resume text through four stages, each grounded in a different model from formal language theory: regular expressions for information extraction, finite-state transducers for qualification normalization, finite automata for pattern recognition, and context-free grammars for structuring the final candidate profile. Before implementing the system, it is useful to look at how each of these models has been applied to similar problems, both inside and outside the specific domain of resume processing, and at the tool that will be used to implement the automata and transducer components.

## Information extraction with regular expressions

Automated resume screening begins with turning free text into structured fields, and regular expressions remain a common first tool for this task precisely because resumes, despite their variety, still follow recognizable surface patterns for things like email addresses, dates, and section headers. A rule-based extractor presented in [1] applies a distinct regular expression to each of eight resume fields (name, date of birth, email, phone number, GPA, gender, nationality, and address), after a preprocessing step that standardizes date formats and expands acronyms such as CGPA into GPA. The system reached 96.4 percent precision on the test set, with seven of the eight fields scoring perfect precision; the address field was the weakest at 71.6 percent, which illustrates a limitation worth keeping in mind for ResumeLens as well, namely that free-form fields without a consistent internal structure are harder to capture with a fixed pattern than fields with strong lexical cues. A related system in [2] combines regular expressions with named entity recognition: regex rules detect universities and degrees by matching on keywords such as University or Bachelor of, while NER handles names and skills that do not follow a fixed textual pattern. Read together, these two sources support a practical design decision for Stage 1 of ResumeLens: regular expressions work well on fields with a predictable lexical shape such as emails, phone numbers, known technology names, or degree titles, and less well on fields that depend on context or free form writing, which is why extraction in this project is treated purely as a syntactic first pass, leaving every equivalence and classification decision to the later stages.

## Normalization with finite-state transducers

Once candidate information is extracted as raw strings, those strings still vary in how they spell the same qualification across different resumes, and this is where finite-state transducers come in, since they are the classical model for mapping variable input strings onto a single canonical output. The classical account of transducers in [4] shows how a chain of transformations, each handling one kind of variation such as case, abbreviation, or spelling, can be composed into a single automaton that performs the whole translation in linear time, which is the same principle Stage 2 of ResumeLens relies on when it chains together the normalization of several unrelated qualifications into one pipeline. The use case closer to Stage 2 appears in [5], where weighted finite-state transducers normalize historical text: the central problem is the same one ResumeLens faces at a smaller scale, since a vocabulary of equivalent surface forms, spelling variants across time in that case and abbreviations or naming conventions across resumes in this project, needs to collapse onto a single canonical token before any later stage can treat them as the same unit. The transformations ResumeLens defines, such as JS and Javascript both mapping to JAVASCRIPT, or Scikit-learn and sklearn both mapping to SCIKIT_LEARN, are a direct, much smaller scale instance of the same modeling problem described at length in both sources.

## Qualification pattern recognition with finite automata

Stage 3 classifies a normalized, ordered sequence of qualifications against the pattern expected for a professional profile, which is a textbook application of finite automata as acceptors. The AUTOMETA system in [3] uses a finite automaton compiled from a set of multi-word ontology entries to recognize domain specific terminology in free text in linear time, without any training phase, reaching 91 percent accuracy on a 100 document test set drawn from 23 combined ontologies. Although its application domain is topic classification rather than resume screening, the underlying argument transfers directly to Stage 3 of ResumeLens: once the vocabulary that matters has been normalized into a fixed set of symbols, a finite automaton is a lightweight and fully interpretable way to decide membership in a language, in contrast to statistical classifiers that need labeled training data and give no explicit account of why a given input was accepted or rejected. This is also the argument ResumeLens needs to make explicit in its own design discussion, since the choice of automata over a learned classifier is not just a course requirement but the appropriate tool once normalization has already resolved the ambiguity in the input.

## Candidate profile language with context-free grammars

The last stage turns the structured result of the previous three into a validated, well formed candidate profile, which calls for a grammar rather than a flat set of fields, since the language needs to support repeated and optional elements such as multiple experiences or multiple skills, with a clear notion of what counts as a syntactically valid profile. The system described in [6] generates synthetic CVs from a context free grammar, which is close in spirit to Stage 4 read in reverse: where that grammar produces valid CV instances from the language it defines, the grammar in ResumeLens needs to validate whether a given structured profile belongs to the language, rejecting any instance that violates its lexical or syntactic rules. The more general argument for why a context free grammar is the right tool for this kind of structured domain language appears in [7], since a CFG, unlike a fixed schema format, can express recursive and repeated structure, such as an arbitrary number of experience or skill entries, without requiring a separate rule for each possible count, which is exactly the requirement for candidate profiles with a variable number of experiences and skills.

## Implementation tool: Pyformlang

Since the guide requires implementing the transducers and automata with Pyformlang specifically, it is worth looking at the library itself rather than only at the formalisms it implements. The library is described in [8] as a Python tool built explicitly for teaching, implementing deterministic, nondeterministic, and epsilon nondeterministic finite automata with conversions between them, finite state transducers, and context free grammars with support for Chomsky normal form, closely following the textbook presentation of each algorithm so that the code maps directly onto the theoretical definitions covered in class. This source is useful for ResumeLens beyond the theoretical papers above because it documents the exact operations the implementation will rely on, such as minimization, equivalence checking, complementation, and grammar to regular language intersection, and it supports the project's own formalization requirement, since every automaton and transducer in ResumeLens can be defined with the same five tuple and seven tuple notation this library is built around.

Taken together, these eight sources confirm that each of the four models ResumeLens relies on already has established, specific precedent outside the narrow context of this assignment. Regular expressions and NLP techniques are actively used for resume parsing, finite-state transducers are the standard tool for canonicalizing variant text, finite automata are an interpretable alternative to learned classifiers for recognizing patterns once input has been normalized, and context free grammars are the right model for a structured language with repeated and optional elements such as a candidate profile. The review also motivates the specific choice of Pyformlang as an implementation tool, since it was built for exactly this kind of exercise, connecting automata, transducers, and grammars under one educational library that mirrors the textbook definitions this project is required to provide.
